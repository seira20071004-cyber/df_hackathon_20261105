# Bridge Work 2.0 適応型相談とモバイル画面

## 試演

`npm run demo` で起動し、http://127.0.0.1:3005/ を開く。Linh で「Bắt đầu hỏi đáp」を選び、「Tôi không thể quét mã vạch. Tôi phải làm gì?」を入力して検索する。「Tại quầy thu ngân」と回答すると、適用判定を通ったガイドが表示される。開くと進捗、戻る操作、全体表示が使える。「Hóa chất bị đổ」を検索すると、候補の代わりに安全確認と連絡の案内が表示される。

## 変更した機能とファイル

| 対象 | 変更 |
| --- | --- |
| `app/page.tsx`、`app/workspace-shell.tsx`、`app/style.css` | 白と淡いグレーを基調に青を使い、相談入力・確認質問・候補・ガイド・チャットを分けた。スタッフと管理者のモバイル下部ナビを用意した。管理者のPC向け画面にも対応する。 |

| `lib/workflow.ts`、`lib/storage.ts` | 組織・現場・承認版・閲覧権限を確認し、意味検索とキーワードで候補を取得する。エラーコード不一致を除外し、Geminiが適用可と返した候補を最大3件表示する。返却直前に公開版・権限を再確認する。候補なしや危険時には管理者への導線を残す。追加回答は相談に保存し、管理者は会話を再分類できる。 |
| `lib/manuals.ts`、`lib/interactive-generation.ts`、`lib/manual-graph.ts`、`app/manual-guide.tsx` | 保護済みコピーの管理者確認後に分類し、構成指針を変える。既存のグラフを共用し、手順・チェックリスト・説明・承認確認をステップの表示形式として扱う。分岐・注意・完了確認・連絡誘導は既存の型を利用する。危険判定のある生成は保留。ナレッジの新規・更新・重複・見送りを候補として管理者に示す。 |
| `app/manual.tsx`、`lib/publication.ts` | スタッフからの版ごとの報告、管理者によるアーカイブ、公開ハッシュへの分類・危険度の追加。報告は公開状態を変更しない。アーカイブは検索から外れる。 |

## 本番設定と制約

- Firebase Auth、Firestore、Geminiの認証、Sensitive Data Protectionは既存の設定手順を利用する。追加の有料リソースは必須ではない。意味検索を使う場合は `GEMINI_EMBEDDING_MODEL` を設定し、承認版に同じモデルの埋め込みを作成する。現在はサーバーでコサイン類似度を計算する。Firestoreのネイティブベクトル検索には別途インデックスが必要。 [Firestoreのベクトル検索](https://firebase.google.com/docs/firestore/vector-search)
- 現場独自の安全案内は Firestore の `organizations/{org}/sites/{site}` の `safety` に `keywords`（文字列配列）、`contact`（連絡先）、`instructions`（承認された案内）を設定できる。設定用の画面は未実装。本文はGeminiで生成せず、設定された文字列を表示する。
- 実Gemini・実DLPでの精度検証、写真添付と画像の機密検査、Firestoreネイティブベクトルインデックス、クラウドへのデプロイは未実施。手順の結果は既存の経路と解決イベントを保存する。選択肢の個別イベント履歴、手順ごとの結果履歴、適用条件や除外条件の独立した管理項目は今後の拡張。 [Geminiの構造化出力](https://ai.google.dev/gemini-api/docs/structured-output)

## 検証

本番ビルド、型チェック、全73件の自動テスト、起動中APIのスモークテスト5件が成功した。統合テストには公開版の再利用、他組織の候補除外、報告の非公開性、アーカイブ後のアクセス拒否が含まれる。

指定の20相談は模擬分類を使い、アプリ側の危険度上書きと質問の振り分けを検証した。実モデルの分類精度や、各ケースのマニュアル本文の品質を測定した結果ではない。390px幅のブラウザーで、ベトナム語の相談、追加質問、候補、手順表示、危険時の安全画面を確認した。
