# Bridge Work 2.0 セキュリティ監査（変更前）

2026-11-06。コードとローカルデモを対象とした監査。実Firebase/Google Cloudの設定・契約・IAMを監査したという意味ではない。

| 深刻度 | 所見 | 対応方針 |
|---|---|---|
| Critical（本番への誤配置時） | デモの固定ID認証を本番ビルドでも有効化できる。共有デモは架空データ専用であり実認証ではない | 本番ビルドではデモ利用の明示的許可を要求。本番手順で禁止 |
| High | 生成工程の一部だけメール等をマスク。翻訳・要約・検索・追加回答・出力の共通検査がない | AI呼び出しの共通境界と公開前で機密検査。検査不能時は保留 |
| High | 保存層のJSON分岐で組織スコープを呼び出し側に依存。ID衝突で別組織レコードを更新する防御が弱い | 保存層にも組織・現場・IDの不変条件を追加 |
| High | 認証後のレート制限、組織のAI予算・同時実行数制限がない。ログインAPIも無制限 | Firestoreトランザクションによる共有制限、期限付きAIリース |
| Medium | 編集と承認を同時に送れる経路があり、編集後の版固定が十分でない。旧公開版の独立保持がない | 保存後の同一版のみ承認。公開スナップショットを保持 |
| Medium | 本文サイズ制限前に本文全体をメモリへ読み、ログイン本文は制限前にJSON化 | ストリーム読み込み上限、Content-Type、Origin検証 |
| Medium | 重要操作の監査がマニュアル内の履歴のみ。拒否・生成失敗・利用量超過を追跡できない | 値を残さない構造化監査と組織配下の監査コレクション |
| Medium | App Check未導入、レスポンスの共通セキュリティヘッダー未設定 | 任意のApp Check検証、セキュリティヘッダー |
| Low | スタッフへ返すマニュアルが除外リスト方式で、新しい内部フィールドの漏洩余地がある | 公開用フィールドの許可リスト |

確認済みの既存防御：Firebase IDトークンを失効確認付きで検証、role/organizationIdはサーバーのプロフィールから取得、Firestore/Storage Rulesは全拒否、チャットは本人または同じ組織・現場の管理者のみ、検索前にスコープを制限、未承認マニュアルは非公開、Structured Output＋Zod＋根拠・グラフ検証、コード/HTMLの実行なし、画像はdata URL限定で再デコード。クライアントへのGeminiキー露出や、他組織を直接取得するAPIは今回のコード調査では確認していない。

実装は既存の組織/現場階層を維持し、追加フィールド・追加コレクションで行う。既存データの削除・一括移行、クラウドAPI有効化、課金・IAMの実変更は行わない。
