# Bridge Work：対話型マニュアル実装

## 既存構成と変更範囲

Next.js App Router / React / TypeScript / Zod。認証は既存の Firebase Authentication とサーバー側権限検証を再利用する。デモは JSON、実環境は Firestore の `organizations/{organizationId}/sites/{siteId}` 配下。相談ドキュメント内に会話を保持する。従来のマニュアル、配信、画像挿入、A4出力は互換性を維持する。

## 処理フロー

1. 解決ボタンは解決方法の入力なしで押せる。相談を終了し、下書きを一度だけ保存する。
2. Next.js `after()` で生成を実行する。相談終了のレスポンスは生成完了を待たない。
3. 情報抽出：発言の役割、ID、原文を渡し、各事実に実在する引用を要求する。原因不明や成功した操作の不明さを保持する。引用の存在・管理者の権威・訂正前情報を検証する。
4. 不足判定：正確性・安全性・再現性に必要な質問だけを最大3件返す。管理者の追加回答は元のチャットと別に保存し、抽出から再実行する。最大3ラウンド。同じ質問の反復や上限到達は保留する。
5. 構成設計：STEP / BRANCH / WARNING / CHECK。根拠のない条件・解決基準・操作は生成しない。行き先が不明な場合は管理者に確認する。危険な操作には許可の根拠を要求する。
6. 品質検証：別プロンプトで意味・条件・安全性・完全性を照合し、全ブロックの結果を保存する。アプリでもJSON、根拠、遷移先、重複、循環、到達不能を検証する。設計の修正は最大2回。失敗時は非公開。
7. 管理者が会話・追加情報・作業条件・権限を確認して承認する。管理者による変更は別の確認情報として記録し、AI照合済みと誤表示しない。
8. 公開済みかつ同じ組織・現場のマニュアルのみ検索する。スタッフが候補の適合性を確認して開く。開始・解決・未解決を記録し、未解決時はマニュアルを参照した新しい相談へつなげる。

## データと安全対策

`Manual.program` が対話型JSON。既存 `content` は互換用の投影。`revision`、`approvedBy/approvedAt`、`reviewState`、`clarification`、`extraction`、`quality`、`audit`、任意の `embedding` を追加。`updatedAt` で楽観ロックする。編集・非公開化後は古い版の閲覧・結果送信を拒否する。

`manualUses` はスタッフ、版、セッションID、経路、結果を保持する。同じ解決イベントや結果送信を重複保存しない。未解決記録と引き継ぎ相談を原子的に保存する。スタッフへは生の抽出・引用・管理者追加回答・監査情報を返さない。

AIへの送信ではユーザーID・送信者名フィールドを省き、メール・形式付き電話番号・処理実行者の氏名をマスクする。自由文中の全個人情報を完全には検出しないため、実運用前には必要に応じて組織の個人情報フィルターを追加する。50発言または100KBを超える会話は黙って切り捨てず保留・再実行対象とする。チャットは参考データとして渡し、内部の命令を実行しないよう各工程で指示する。

## 環境変数

既存の Firebase 設定・認証はそのまま利用する。AI設定はサーバー専用で、クライアントへキーを渡さない。

| 変数 | 内容 |
|---|---|
| `GOOGLE_CLOUD_PROJECT` / `GOOGLE_CLOUD_LOCATION` | Vertex AI のプロジェクトとロケーション。Cloud Run の実行用サービスアカウントで ADC を利用 |
| `GEMINI_MODEL` | 生成・翻訳用。既定 `gemini-2.5-flash` |
| `GEMINI_REVIEW_MODEL` | 品質検証用の任意モデル。未設定なら同じモデル |
| `GEMINI_GENERATE_IMAGES` | 既定無効。`true` のときのみ任意の図解生成を追加 |
| `GEMINI_IMAGE_MODEL` | 任意の画像生成用。今回の対話型機能には不要 |
| `GEMINI_EMBEDDING_MODEL` | 任意。利用プロバイダーで対応するモデルを指定して再承認すると索引を作成 |
| `GEMINI_SIMILARITY_MIN` | 意味検索の最低コサイン類似度。既定 `0.72`。実データで調整が必要 |

Embedding未設定・利用失敗時は既存のGemini候補判定と文字ベース検索を利用する。インデックスのない旧版は再承認で作成する。多言語は日本語・英語・ベトナム語に対応し、訳文の構造と意味保存を検証する。翻訳に失敗した言語は日本語にフォールバックし、未検証の訳を公開しない。

## 検証方法と現時点の制約

`npm run build`、`npm run check`、`npm test`。単体テストは注入可能なAI関数、API統合テストは公式SDKのHTTP境界をモックする。単純手順、分岐、不足情報、原因不明、成功した手段不明、危険操作、外国語、不正JSON、API障害、重複解決、不正遷移、別組織へのアクセスを対象とする。

実際のGemini/Vertex接続・実モデルの精度・費用・翻訳品質はこのモック検証では保証しない。現在の共有デモではAIを無効にし、手動で作成した架空の対話型サンプルを表示する。

生成状態と試行IDは保存するが、常駐の耐障害ジョブキューは未導入。サーバー停止後の自動再開は行わず、管理者の再生成で復旧する。Cloud Runのジョブ化やCloud Tasks導入は本番運用時の拡張候補。Firestore実サービス・実認証でのエンドツーエンド検証も別途必要。

編集履歴は直近30件の変更メタデータを保持し、追加回答に変更内容を記録する。全版のスナップショット復元は未実装。危険性や根拠の意味の判定にはモデルと管理者による確認が必要で、アプリの構造検証だけでは保証しない。

従来型マニュアルの長押し並べ替え・画像挿入は維持する。対話型マニュアルは遷移先で順番を編集し、画像は既存データの表示・印刷に対応する。対話型ブロック専用の画像アップロード・長押しでの遷移変更は今後の拡張。紙には全分岐を配置し、操作画面のように回答で表示を切り替えることはできない。
